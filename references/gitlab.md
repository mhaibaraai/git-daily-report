# GitLab 取材

GitLab 既可以为 EOM 提供代码素材，也可以单独生成普通报告。普通报告使用 `material --mode gitlab`，其余保存、查看和导出命令保持相同模式和日期。

## 项目与作者

- 优先读取配置的 `projects`，并合并匹配工单的映射项目；推荐使用 `mappings[].project_name` 按 EOM“项目名称”列关联 `gitlab_project`，同项目不同工单共用该映射。明确配置分支时使用该分支。
- 没有指定项目时，从当前令牌用户的推送事件发现候选项目，不遍历全部可见仓库。
- 事件存在保留期和批量推送信息限制，因此自动发现会返回覆盖范围提示；需要完整覆盖时配置项目。
- 指定项目而未指定分支时，读取该项目全部分支中的区间提交；已指定分支不会被 `all=true` 覆盖。
- 默认识别当前账号的作者姓名和邮箱，或使用配置的精确作者标识。团队报告可以显式使用 `all_authors`。

## 日期与合并

事件日期查询向两端各扩展一天，再用提交者时间和报告时区过滤实际提交。普通提交的日期只是提交者时间，不代表实际工作发生日。

本人操作的合并提交按两个父提交比较，保留其引入的提交作为“集成”素材；不再要求引入提交的作者也是本人。集成素材的 `day` 为合并发生日，`committedAt` 保留原提交时间，`integrationSha` 指向合并提交。原作者的开发成果不能描述为合并者独立开发。

同一项目同一 SHA 只保留一份；同一提交既属于本人编写又出现在合并展开结果中时，优先保留本人编写记录。不同实例的状态独立。

## 输出与异常

每条素材包含项目标识、SHA、标题与消息、报告日期、原提交时间以及 `contribution`（`authored` 或 `integrated`），不输出令牌或独立作者邮箱字段。提交文本可能仍含内部信息，代理按交付范围筛选。

- 分页完整读取，达到上限显式警告。
- 合并展开失败时保留集成记录并提示，不能据此编造具体实现。
- 个别项目失败时返回其余素材并附限制；全部请求的项目均失败时命令失败。
- 身份验证、权限、网络或格式错误不会作为“没有提交”成功返回。
- 请求不跟随重定向；只读请求可以有限重试，不自动改变分支或推送代码。

GitLab API 行为参考：[Events API](https://docs.gitlab.com/api/events/)、[Commits API](https://docs.gitlab.com/api/commits/)、[Repositories API](https://docs.gitlab.com/api/repositories/)。
