# 取材脚本

`scripts/collect_git_activity.py` 只读取本地 Git 历史，不修改仓库，不发起网络请求，不读取环境配置文件。运行需要 Python 3.9+、支持 `--since-as-filter` 的 Git，以及可用的系统时区数据库。

## 参数

| 参数 | 语义 |
| --- | --- |
| `--repo PATH` | 目标工作树；可以重复，默认当前目录。相同仓库的子目录会去重 |
| `--period NAME` | `today`、`yesterday`、`this-week`、`last-week`；默认 `today` |
| `--since DATE --until DATE` | 两者必须一起使用，格式为 `YYYY-MM-DD`，包含首尾日期；不能同时使用 `--period` |
| `--timezone NAME` | 系统支持的 IANA 时区；`UTC` 无需时区数据库，默认系统本地时区 |
| `--ref REF` | 单个提交、分支或标签，默认 `HEAD`；每个目标仓库都必须存在该引用 |
| `--author PATTERN` | Git 作者正则表达式，可重复，多个条件为“或”；默认不筛选作者 |
| `--limit N` | 每个仓库最多输出的提交数，正整数，默认 500；超限返回显式警告 |

例如按作者整理上周记录：

```bash
python3 /path/to/git-daily-report/scripts/collect_git_activity.py \
  --repo /path/to/repository \
  --period last-week \
  --author 'author@example\.invalid' \
  --timezone UTC
```

作者参数使用 Git 原生的模式匹配语义，不代表严格身份验证。需要核对个人归属时，使用明确的作者模式；名称或邮箱中有正则元字符时注意转义。作者邮箱不作为单独字段写入 JSON。

## 记录范围

- 使用提交者时间筛选日期，并转换到报告时区分组。作者时间另行保留；提交日期不等于实际工作发生的日期。
- 默认读取 `HEAD` 可达历史，包括已合并分支中的普通提交；合并提交本身不输出，避免重复计算分支成果。
- 未合入所选引用的分支不会被读取。需要其他分支时显式指定 `--ref`；不默认遍历全部分支。
- 仅存在于合并提交中的冲突解决变更不在默认素材内。需要分析集成工作时，应补充查看相关合并提交，不凭普通提交列表推断。
- 无作者筛选时，记录可能来自多人；有作者筛选时，合并者集成的他人提交不会自动算为合并者个人成果。
- 只读取已有本地历史。浅克隆、尚未同步的本地分支和提交上限均可能限制完整性。

## JSON 输出

顶层包含：

- `schemaVersion`：当前为 1。
- `range`：包含首尾日期及报告时区；未指定时区时为 `local`。
- `scope`：所选引用、是否筛选作者、使用的日期依据及是否包含合并提交。
- `repositories`：按输入顺序去重后的仓库结果。
- `commitCount`：实际返回的提交总数；截断时不代表完整历史的数量。

每个仓库结果包含 `name`、解析后的 `revision`、`commits`、`shallow`、`truncated`、`warnings`。仓库名相同时用数组位置和输入对应关系区分，不按名称合并。

每条提交包含 `sha`、`parents`、`authoredAt`、`committedAt`、报告时区下的 `day`、`subject` 和 `body`。提交按时间及 SHA 排序。SHA 用于核对素材，不要求放进报告正文。

脚本不主动输出远程地址、本机绝对路径或作者邮箱字段，但提交正文和仓库名可能包含敏感内容；这不是脱敏工具。代理应按交付范围筛选报告内容。

## 错误处理

- 空分支：成功返回空列表和提示。
- 没有匹配提交：成功返回空列表，不表示当天没有工作。
- 非 Git 工作树、无效引用、无效日期、缺少 Git、读取失败或超时：stderr 返回错误，退出码非零；不返回部分成功的 JSON。
- 未安装所选时区：选择系统已支持的时区，或明确使用系统本地时区；脚本不会自动安装依赖。
- 达到上限：增加 `--limit` 或拆分日期后重新收集，合并素材时按仓库和 SHA 去重。
