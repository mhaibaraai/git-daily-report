# EOM 周报

由 Codex 或 Claude Code 自己写进展，无需单独配置 AI 接口。`dr` 负责拉素材、校验、落盘；网页可调整百分比和工时，通过独立提交操作写入 EOM。

`dr` 不在 PATH 时，在 git-daily-report 仓库里用 `uv run dr` 代替。

## 步骤

1. **定区间**：用户没说就是本周，不传参数；「上周」或具体日期换算成 `--since YYYY-MM-DD --until YYYY-MM-DD`，后续每条命令都带同样的参数。
2. **拉素材**：运行 `dr material [--since D --until D]`。stdout 是 JSON：
   - `rules`：写作规则与输出格式，逐条严格遵守
   - `material`：排期与提交，唯一的素材来源，不得编造
   - `pending`：必须输出的（日期, 工单），一条不能少也不能多

   `pending` 为空就告诉用户没有要写的块。命令失败时脱敏后报告错误（常见是 `EOM_TOKEN` 过期，按 README 重新取）。用户只要求提交已有报告时，跳过素材拉取和生成，避免覆盖本地内容。
3. **写进展**：按 `rules` 写出 `{"items": [...]}`，每项除文本外还包含数值 `rate`（累计百分比，0–100）和 `hours`（当日工时），存成临时目录下的 JSON 文件。进度按日期不得倒退；按工作量分配工时，扣除已填工时后默认每天分满 7.5h，合计不能超限。两者属于估算，不描述为实际测量值。
   百分比严格按工单 ID 独立计算：不同 ID 即使同名，也不继承进度，各自按自身工作阶段在 0–100 内估算。`rateMin` / `rateMax` 和 `previousDay` / `previousMemo` 只约束同一 ID；新 ID 首日不强制为 0。输出始终使用当前 ID。
4. **校验落盘**：运行 `dr apply <文件> [--since D --until D]`，stdout 是 JSON：
   - `failures`：不合格的块与原因
   - `missing`：还没写的块
5. **只重写问题块**：有 `failures` 或 `missing` 时，按原因只重写这些块，写成新文件再 `apply`，已通过的块会保留。必须把保留块和 EOM 已填工时计入日总数。最多重试 2 轮，仍不过的报告给用户。
6. **独立提交**：普通「写周报」只生成。用户明确要求提交时，运行 `dr submit [--since D --until D]`；只要求预览时加 `--dry-run`。生成和校验不代表提交授权。已有日报自动跳过，不覆盖。
7. **修正已填百分比**：用户明确要求重算已填进度时，运行 `dr amend --since <当前工单ID排期首日> --until <最后已填日>`，每个 ID 独立重算，不合并同名工单；把 `changes` 列给用户核对，用户明确要求提交后再 `dr submit` 同一区间。之后重新生成同一 ID 的后续日期。
8. **收尾**：报告生成数量、待复核块和逐日提交结果，提示可运行 `dr` 查看及调整。提交命令返回非零时仍读取其 JSON，说明失败、冲突或待核实日期，不把部分成功说成全部完成。

## 边界

- 不直接拼 curl 或自行读取凭据；提交统一调用 `dr submit`
- 超时后不反复提交。工具会回读核实并保存待核实状态；只有用户明确要求主动重试时才使用 `--retry-unknown`
- 不要把 `material` 里的提交原文、文件名、英文标识符直接搬进进展
- 不要读取或输出 `.env` 里的凭证
