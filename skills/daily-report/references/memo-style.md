# 三段式 memo 写作规范

三段式是导出视图，用于粘贴回 EOM 日程表页面。段名固定，不可改动：

```text
具体任务：…；…
关键数据：…；…
问题解决过程：…；…
```

条目之间用全角分号 `；` 连接，每段占一行。段标题始终在场——缺内容是缺内容，不是缺段。

## 各段写什么

### 具体任务

当天实际做的事，动宾结构，一件事一条。

素材来自工作点的明细，即未命中问题关键词的那些条目。明细本身来自 GitLab 提交标题（合并提交已展开成它带进来的那批），以及工作项完成这类节点记录。

### 关键数据

可量化的产出。EOM 前端期待「N 条／N 个／从 X 优化至 Y」这类表述。

提交次数由规则层数出来，**不要修改这个数字**，只调整措辞。数不出来的量化指标不要补——没有的就是没有。

### 问题解决过程

遇到什么问题、怎么定位、怎么解决。素材来自命中「修复／定位／排查／异常／报错／优化／解决／调整」关键词的明细。

## 改写原则

- **只调措辞，不动事实。** 数字、工作项标题、项目名一律照搬原值。
- 去掉 `feat:` / `fix:` 这类前缀残留和分支名噪音，换成人话。
- 一条明细讲一件事。原始提交把两件事写在一起时可以拆开，但不要合并出原文没有的因果。
- 抽不出内容的段落留空，如实汇报，**绝不编造**。
